# Plugin CLI scope

These notes correct the assumptions in the twenty plugin issues before implementation. They distinguish documented behavior from an implementation proposal. A native host adapter, a preset-container reader and an independent DSP implementation are separate deliverables. Surge has a tested adapter. Saturn 2 and Pro-Q 4 now have native reference rendering through the [VST3 CLI](VST_CLI.md), without independent algorithm implementations.

## Open engines

**#2 Vital.** The pinned public source already contains a [headless entry point](https://github.com/mtytel/vital/blob/636ca0ef517a4db087a6a08a6a8a5e704e21f836/src/headless/main.cpp) and a [native preset loader/offline writer](https://github.com/mtytel/vital/blob/636ca0ef517a4db087a6a08a6a8a5e704e21f836/src/common/synth_base.cpp). Its flags differ from the proposed NZRdsp interface. The writer fixes output at 44.1 kHz stereo Int16, adds a proportional tail and processes full 64-sample blocks. The first task is a Windows console build and adapter with explicit rate, tail and failure handling. Do not strip a GUI that the existing headless target already excludes. The [source policy](https://github.com/mtytel/vital/blob/636ca0ef517a4db087a6a08a6a8a5e704e21f836/README.md) treats engine licensing, factory content, trademarks and web services separately; the public source is older than current product binaries.

**#6 Dexed.** The [current source layout](https://github.com/asb2m10/dexed/blob/fea2f0f0f2c397799f59b27eb11c038cd34b22c5/README.md) separates core, engine, MIDI, parameters and UI. Dexed is GPLv3; its MSFA component has a different license. Reusing MSFA alone does not reproduce the alternative engines in the full plugin. The [cartridge parser](https://github.com/asb2m10/dexed/blob/fea2f0f0f2c397799f59b27eb11c038cd34b22c5/source/core/Cartridge.cpp) and [program representation](https://github.com/asb2m10/dexed/blob/fea2f0f0f2c397799f59b27eb11c038cd34b22c5/source/core/Program.h) must retain SysEx validation, voice selection and semantic parameter mapping. The 155-byte program representation is not a list of 155 independent synthesizer controls. Prefer a console harness around the existing audio processor when full Dexed compatibility is the target.

**#7 Surge XT.** Upstream's [command-line host](https://github.com/surge-synthesizer/surge/blob/d8b4a7bf97b39d0558830cd4799642247349bea2/src/surge-xt/cli/cli-main.cpp) is a realtime audio/MIDI/OSC program. The separate [native Python binding](https://github.com/surge-synthesizer/surge/blob/d8b4a7bf97b39d0558830cd4799642247349bea2/src/surge-python/surgepy.cpp) provides the required offline patch, parameter and note processing. NZRdsp now builds that engine and wraps it with Rust commands; see [Surge CLI](SURGE_CLI.md). Native WAV generation, direct-core comparison and the metadata/catalog interface are implemented. A GUI reference comparison remains outstanding, so the issue stays open. Factory assets remain outside this repository.

## Commercial synths

**#1 Serum 2.** The [version-specific feature document](https://static.xferrecords.com/Serum%202%20What%27s%20New.pdf) describes three configurable main oscillators with Wavetable, Multisample, Sample, Granular and Spectral types, plus the separate supporting oscillators. A Serum-1-style wavetable renderer would cover only part of this issue. The [installation guide](https://xferrecords.com/web-manual/serum-2/installing-serum) lists VST3, AU and AAX. The issue's CLAP claim needs correction or evidence from a specific installed build. A [preset tool's author](https://github.com/KennethWussmann/serum-preset-packager) documents the .SerumPreset container as a metadata header plus Zstandard-compressed CBOR; that is developer evidence about the container, not an official engine specification. Native state, external sample assets and oscillator mode must all be recorded in reference fixtures.

**#3 Massive X.** NI's [FAQ](https://support.native-instruments.com/support/solutions/articles/69000879946-massive-x-frequently-asked-questions) distinguishes Massive X from classic Massive. Its [preset sharing guide](https://community.native-instruments.com/discussion/47046/how-to-export-and-share-your-massive-x-presets) uses .nksf, so the issue's .nmsv example targets the wrong product. The [oscillator manual](https://docs.native-instruments.com/ni-tech-manuals/massive-x-manual/en/wavetable-oscillators) describes named oscillator modes rather than a single generic modern mode. Preserve the modular routing and modulation state when defining a fixture. A classic Massive implementation or preset converter does not establish Massive X compatibility.

**#4 Pigments 6.** The [version 6 manual](https://dl.arturia.net/products/pigments/manual/pigments_Manual_6_0_0_EN.pdf) has two main slots offering Analog, Wavetable, Sample, Harmonic and Modal, with Granular inside Sample and a separate Utility engine. The issue omits Modal and counts Granular incorrectly. Its exported preset container is .pgtx. Pin the actual product version and assets before comparing output; a current generic download page is not a specification for version 6. Start with single-engine fixtures, then test layered slots and routing.

**#5 DUNE 3.** The [product description](https://www.synapse-audio.com/dune3.html) includes VA/FM/Wavetable synthesis, dual filters, modulation and two master FX buses. The [.FXP format named by its manual](https://www.synapse-audio.com/DUNE-36-Manual.pdf) describes the container, not the internal state schema. Unison, modulation timing, filter mode and asset identity belong in the reference. A generic VA oscillator and a biquad do not establish its documented filter/voice behavior.

## Distortion and dynamics

**#8 Saturn 2.** Its [manual](https://www.fabfilter.com/help/saturn) describes up to six bands and modulation. The [quality settings](https://www.fabfilter.com/help/saturn/using/inputoutput) are 8x and 32x, rather than the issue's 16x maximum. Linear-phase settings apply to specific crossover/oversampling paths. Specify band routing, feedback, level and modulation as well as the distortion style. Static transfer curves alone are insufficient for stateful presets.

**#9 Decapitator.** The [manufacturer manual](https://www.soundtoys.com/wp-content/uploads/Decapitator-Manual.pdf) defines styles A/E/N/T/P: Ampex 350 preamp, Chandler/EMI TG, Neve 1057, and Culture Vulture triode/pentode. Correct the issue's style mapping before naming CLI choices. Drive, Punish, pre-saturation tone/low cut and post-processing affect the result. Reference tests should separate level-dependent harmonic response from frequency and transient response; a named static curve is not yet a matching model.

**#10 Thermal.** The [manual](https://shop.output.com/app/uploads/2020/10/Thermal_User_Guide.pdf) has three stages, each offering nineteen distortion choices, rather than five stages. Stage filtering, feedback, width and final tone processing belong in the signal path. Begin with one stage and fixed modulation, verify it, then extend to the documented stage routing. An implementation with five generic serial waveshapers would target a different processor.

**#11 Spicerack.** The [manual](https://process.audio/en/products/spicerack/manual) defines Drive, Tube, Amp, Lo-fi and Fuzz plus wet-path gate and filtering. It explicitly excludes Calibration, Linear Phase and Oversampling from preset storage. Consequently, loading a native preset alone cannot establish a reproducible configuration: the manifest must also capture these global settings. Gate detector filtering, output level and mix need explicit fixtures.

**#12 Pro-C 2.** Use the [version 2 PDF](https://www.fabfilter.com/help/ffproc2-manual.pdf), because unversioned help may describe a newer product. Its eight styles have different behavior; Vocal has automatic ratio/knee. Mix scales gain change through a range extending beyond ordinary dry/wet blending. Lookahead, hold, knee, oversampling and sidechain configuration must be captured. Finding an installed Pro-C 3 binary does not verify this version-specific issue.

**#13 SPL Transient Designer Plus.** Its [manual](https://files.plugin-alliance.com/products/spl_transient_designer_plus/spl_transient_designer_plus_manual.pdf) describes differential envelopes, attack/sustain, detector filtering, sidechain, stereo linking, mix and soft clip. It does not disclose all detector constants or the complete discrete-time topology. Keep a generic differential-envelope experiment separately named until reference behavior is measured. Test a hit at several input levels, not just one normalized transient.

**#14 DS-10.** The [manual](https://support.xlnaudio.com/hc/en-us/articles/6843838796573-DS-10-Drum-Shaper-Manual) documents Attack, Sustain, Mojo, Kick/Snare/Bus modes and Classic/Natural/Smooth algorithms. It does not document independent transient/tone/noise stem extraction or the issue's fast/medium/slow selector. Implement the documented controls first. Any component-separation feature would be an additional NZRdsp design, with its own name and tests.

## Granular processors

**#15 Portal.** Documented [grain controls](https://support.output.com/en/articles/10297851-grain-controls) include timing-dependent density, offset, grain size/count, pitch/scale, pan, stretch and grain delay. Its [two post-granulator FX slots](https://support.output.com/en/articles/10297854-effects) have a defined position between granulator and master mix controls. Units and routing must match the chosen mode. A single grain trigger interval in milliseconds cannot cover every tempo-synchronized configuration.

**#16 FRAGMENTS.** The [manual](https://dl.arturia.net/products/efx-fragments/manual/efx-fragments_Manual_1_0_0_EN.pdf) describes Classic/Texture/Rhythmic modes, sequencing and configurable two-slot FX routing. A documented Multi-Filter FX slot does not prove an independent filter per grain. The [support guide](https://support.arturia.com/hc/en-us/articles/4494280268306-Efx-FRAGMENTS-General-Questions) explains cases where transient capture or stopped host transport produces silence. A silent offline render therefore needs a transport/capture check before being treated as a broken plugin.

**#17 Graindad.** Its [manual](https://downloads.sugar-bytes.de/manuals/Graindad.pdf) describes density modes, host/transient clocks, sequencing, modulation and record/play buffer behavior. The nominal 64-grain limit has an audio-rate-triggering exception. Do not hard-code a universal limit based solely on the headline. Randomization requires a repeatability measurement before using a sample-by-sample null test. Log tempo, trigger mode, capture state and reset behavior alongside parameter values.

## Time, pitch and dynamic EQ

**#18 Pitch 'n Time Pro.** The [Pro download page](https://serato.com/pitchntime-pro/downloads) identifies an AudioSuite product for Pro Tools. The [product page](https://serato.com/pitchntime-pro) documents independent time/pitch processing and variable curves, but does not establish the issue's guessed implementation or quality flags. A normal VST3 host cannot directly load this AudioSuite build. Verify an actual supported reference workflow before promising a generic headless command. Stereo coherence is an explicit [reference property](https://support.serato.com/hc/en-us/articles/202297614-Is-Serato-Pitch-n-Time-Pro-phase-coherent), so tests must include paired channels.

**#19 RX Radius.** The [Time & Pitch documentation](https://s3.amazonaws.com/izotopedownloads/docs/rx9/en/time-and-pitch/index.html) distinguishes this module from Variable Time and names Radius, Radius RT and Solo Instrument options. The RX suite's plugin support does not establish a separately loadable Radius VST3 module. First inventory the installed version and actual module interface. A generic time stretcher may be useful, but it must not be presented as a verified Radius implementation.

**#20 Pro-Q 4.** The [dynamic EQ guide](https://www.fabfilter.com/support/help-detail?alias=pro-q&url=using%2Fdynamic-eq) describes program-dependent behavior and relative timing controls, rather than a conventional independent ratio for every band. [Spectral Dynamics](https://www.fabfilter.com/help/pro-q/using/spectral-dynamics) acts within a band and is not reproduced by a single band-level detector. Separate static EQ, dynamic bands, spectral behavior and phase modes in the implementation and fixtures. Matching one static frequency response does not verify the dynamic processor.

## Host and verification plan

The [VST3 processing lifecycle](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical%2BDocumentation/Workflow%2BDiagrams/Audio%2BProcessor%2BCall%2BSequence.html) includes state loading, bus setup, processing setup and activation. Follow it instead of calling an assumed internal processing address. Native preset files, VST3 .vstpreset state and a host's saved state are different interfaces.

[Pedalboard](https://github.com/spotify/pedalboard/blob/05e8f0b3c4851e77485d7e842dc0355b44106471/pedalboard_native/__init__.pyi) exposes effect and MIDI-instrument rendering, plugin parameters and VST3 preset/state access. Its presence is not evidence that a particular commercial plugin renders correctly. Explicitly append silence for tails, keep processing state continuous across chunks and compare reset behavior. A separate process limits the effect of a plugin crash on NZRdsp.

[DawDreamer](https://github.com/DBraun/DawDreamer/blob/e0daff3c218fbb816e6ca01b54267495cdcfaa71/docs/user_guide/plugin_processor.rst) offers another native host route. Its [render engine](https://github.com/DBraun/DawDreamer/blob/e0daff3c218fbb816e6ca01b54267495cdcfaa71/Source/RenderEngine.cpp) supplies BPM and PPQ; the inspected implementation does not establish arbitrary complete transport semantics. This distinction matters for synced grains, sequences and LFOs. Neither inspected host supplies an AudioSuite interface for Serato Pro.

For each implemented command, retain the native version, module hash, preset hash, external asset identities, raw/display parameter values, sample rate, block size, tempo, note/input timing, tail length, latency policy and output hash. Test identical runs before defining an error threshold. Use exact comparisons for deterministic fixtures; measure timing, spectrum, envelope, stereo behavior and repeated-run variation for randomized or analog-style processing. A command is not complete merely because it writes a nonzero WAV.

## Remaining work

The twenty issues stay open until their requested implementation and reference checks are complete. Surge currently has the native adapter and regression tests; its remaining items are listed in its guide. Saturn 2 and Pro-Q 4 have native reference-host fixtures and streamed processing checks. Other entries are researched implementation scopes, not delivered engines.
